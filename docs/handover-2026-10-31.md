## What was done today (in order)

1. **Hallway stutter (Debilitas' entrance)**: only in the release build. gcc 13 turns block copies into `rep movsq`,
   which is very slow on AMD CPUs into write-combined GPU memory (the command rings). Fix: `ring_put` (memcpy through a
   volatile pointer) and `-mstringop-strategy=libcall` in `hgbuild.py` and the Makefile (`5600e10`, `3904eba`; the
   release rule check requires both to match). Unpaced worst moment 0.93-1.10x became 1.26-1.31x (the user's "20 %
   extra" margin target). Before that: 256 command buffers in rotation, interpolation matching fixes (`cc18331`,
   `f0021b9`).
2. **Widescreen** (Options > Aspect ratio, up to 21:9): the 3D view widens, 2D stays 4:3 (`0be665f`, `8ff8f29`). Fixes
   from the playtest: the see-through examine box (2D triangles squeezed too, `7caa580`) and the hitch before the
   Capcom logo (the GS starts with the program when windowed, `fe096ac`).
3. **HD letters** (a Fable agent): the game's glyphs redrawn at high resolution; the first version was "too clean",
   the second ("tent" filter, soft edge as on the PS2) accepted ("text does look a bit better"). In the release pack
   as BC7 (13 sheets, 81 MB; pack now 1,407 files in `texwork/release_textures`).
4. **GPU renderer rework** (`ae70fa0`, `1273d0e`): the N x N sub-pixel copies of GS memory interleaved per word, a much
   smaller shader (424 to 64 KB of code), geometry evaluated per copy in place, `precise` arithmetic in the copies too
   (bit-identical run to run). x6 costs about a third less; x4 barely changed. Dropped experiments: a small-batch path,
   exact in-place fields (26 % slower), bin lists. "6x on lower-tier hardware" is not reachable (cost grows with the
   square of the factor); the user chose FSR + resolution tiers instead.
5. **AMD FSR 1** (MIT, `recomp/third_party/fsr1`; EASU + RCAS in the present pass; Options > Upscaling, FSR / Bilinear;
   `fc35025`, `b617552`). Used only when the picture is smaller than the window. OptiScaler investigated: not
   applicable (it hooks DLSS/FSR2+ inputs of games that have them; we have no motion vectors or depth for it).
6. **High-res glow** (Options > Soft focus, `0e52818`, `efab3c5`): the user saw "interlaced lines" on Fiona's face
   outdoors. Not a copies bug: the game's glow layer is drawn at 256x224/128x112 and stretched back, which shows
   doubled lines at high factors. Now the enlarging sprites read all copies as one N-times finer picture (`sample_hr`).
   First version (bilinear) made outdoors visibly less smooth; now one nearest read.
7. **Keyboard keycaps** (a Fable agent, `09fb8f4`, merged `4eb47a1`): the PlayStation symbols in the game's text become
   keycaps of the player's bindings when playing on the keyboard; the Controller page lists the keys. User: "keycaps
   looked perfect".
8. **G10 picture reference re-made** for strict copies + high-res glow (`afd0f5b`, approved by the user; the old one
   kept as `scratch/pic_ref_x5i_20261031_beforestrict`). Check after: 24/24 bit-identical.
9. **GPU-loss fallback** for bug report #2 (`600002a`): on VK_ERROR_DEVICE_LOST the game switches to the software GS and
   SDL presenting and carries on (worker threads started: 1.00x). Test switch: `HG_GSVK_LOSE=VB`.
10. **Security hardening** from the 2026-10-27 audit (`035f68b`): replays never follow links (Windows reparse points,
    POSIX lstat), DDS size check first and mip count clamped, ISO reader caps (seen set, 1 MB directory, 100k entries),
    launcher: explicit-length conversion, bounded command line, `LoadLibraryExW(..., LOAD_LIBRARY_SEARCH_SYSTEM32)`.
    Tested with a crafted recording, DDS and ISO; launcher compiled for Windows (zig cc).
11. Docs: release page draft, crash-reports (ask for the `card` folder, F9 marks), known-issues (speed, suggested
    resolutions per GPU class), options-menu, gpu-renderer (FSR, glow, compiler notes), THIRD_PARTY_NOTICES (FSR).
12. `main` fast-forwarded to the work branch; both bundles built and verified (above).
